BAGIAN 01 • PROBLEM STATEMENT

Kilas Balik: Inefisiensi Fatal Random Scheduling (Minggu 3)

Pada tugas Minggu 3, penjadwalan acak pada CloudSim menghasilkan kegagalan distribusi beban yang ekstrem:

⚠️ Kelemahan Fatal Random Scheduling:

  • Makespan Membengkak: Menyentuh 1.951+ detik (32+ menit) pada 500 tasks.
  • Severe Bottleneck: VM Small Yogyakarta (800 MIPS) terbebani 99.9%, antrean macet.
  • Kapasitas Terbuang: VM Large Surabaya (6.000 MIPS) menganggur (*idle*) utilisasi < 15%.
  • Ketimpangan Ekstrem: LBI berada di level kritis 1.80 s.d 2.30.

🎯 Misi Solusi AOA yang Baru:

  • Memetakan tugas secara cerdas sesuai kapasitas MIPS tiap VM.
  • Memangkas Makespan hingga 51.5% lebih cepat (2x lipat).
  • Menaikkan Throughput dari 0.23 ke 0.47 tasks/detik.
  • Menyeimbangkan beban (LBI turun) dan memotong biaya sewa cloud.

BAGIAN 03 • MATEMATIKA AOA YANG BARU

Mengapa Memilih AOA? Keunggulan 4 Operator Aritmatika

AOA (Abualigah et al., 2021) mengoptimalkan alokasi cloud melalui 2 fase matematis terencana:

1. Eksplorasi Global (÷ & ×)

Menghasilkan lonjakan nilai acak tinggi (diibaratkan helikopter pengintai). Agen pencari melompat bebas antar-datacenter → Bebas dari jebakan optimum lokal (*local optima avoidance*).

2. Eksploitasi Presisi (-, +)

Menghasilkan dispersi rapat dan halus. Agen menyisir detail alokasi di sekitar target terbaik, memastikan tugas terberat terkunci tepat di VM 6.000 MIPS Surabaya.

⚙️ Pengendali Dinamis: Saklar MOA & Pengecil Langkah MOP

MOA secara linier beralih dari eksplorasi (0.2) ke eksploitasi (0.9), sementara MOP menyempit secara non-linear (α = 5) memastikan konvergensi presisi tinggi di akhir iterasi.

BAGIAN 04 • DEPLOYMENT REAL-WORLD

Bagaimana Program AOA Diterapkan & Dijalankan di Real World?

Di lingkungan cloud industri nyata, AOA beroperasi sebagai Dynamic Broker Dispatcher Engine:

1. Workload Ingestion (REST API / Kafka)

Pengguna mengirim batch pekerjaan ilmiah (panjang instruksi MI & ukuran input MB) melalui API Gateway ke antrean broker.

2. Live Telemetry 3 Datacenter

Agent monitoring (Prometheus) memantau status daya 10 VM dan latensi jaringan fisik (Surabaya-Jakarta 15ms, Surabaya-Yogya 8ms).

3. Optimasi Real-Time AOA (< 0.5 detik)

Solver AOA menghitung permutasi alokasi optimal (vektor ID VM 0..9) tanpa membebani overhead waktu tunggu.

4. Remote Dispatch (Docker / SSH / K8s)

Broker mendispatch kontainer tugas secara paralel ke VM Large Surabaya, Medium Jakarta, atau Small Yogyakarta sesuai jadwal optimal.

🎙️ Panduan Bicara (Babak 5): Tegaskan ke dosen bahwa ini bukan sekadar rumus abstrak! Di industri nyata, AOA dipasang di Cloud Controller yang secara dinamis menjadwalkan ribuan container microservice ke server fisik di berbagai kota.
BAGIAN 05 • IMPLEMENTASI PROGRAM

Bedah Kode program_aoa_vs_random.py & CloudSim Java

Program kami dibangun modular dalam dua bahasa (Python Real-World & Java CloudSim 7.0.1):

1. Continuous-to-Discrete Mapping

Operator AOA menghasilkan koordinat kontinu yang kemudian dibulatkan secara deterministik (round(val)) dan dibatasi ke indeks VM valid [0..9].

2. Proteksi Elitisme (Best-So-Far Tracker)

Jadwal dengan Makespan terbaik selalu disimpan di tiang suar emas ($S_{best}$). Jadwal tidak akan pernah mengalami degradasi kualitas di setiap putaran.

3. Real-World Dispatcher

Menghitung waktu transfer file input, latensi antarkota, waktu pemrosesan CPU, Makespan ($T_{\max}$), Throughput, dan biaya sewa ($0.03/detik).

4. Validasi Statistik Objektif

Setiap skenario diuji 10 kali secara independen dengan random seed berbeda untuk menjamin keabsahan statistik (*mean & std dev*).

BAGIAN 07 • KESIMPULAN & Q&A

Kesimpulan Akademik & Sesi Tanya Jawab

  • Random Scheduling Terbukti Tidak Layak: Menimbulkan antrean macet di VM kecil dan membiarkan VM besar menganggur.
  • AOA yang Baru Terbukti Unggul Mutlak: Berhasil menyeimbangkan beban komputasi dan memangkas waktu proses hingga 51.5%.
